# Contributing

Thank you for considering contributing to this project, and I appreciate that you've opened this document to learn about these guidelines!

## Issues

When you post an issue it should be clear and actionable.

Bug reports should concisely summarize what was expected to happen, what actually happened, and how to reproduce the effect.

Feature requests are accepted but should keep in mind that this codebase is already kind of cluttered. Architecture for new features should consider how they can fit into existing patterns or establish extensible patterns to use later.
## Pull Requests

A pull request should contain the minimum changeset needed to implement a feature or fix an issue without disrupting other features. The pull request should be accompanied by a description of the changes, why they are needed, and how to test them.

Be prepared to answer questions about any particular line of code!
